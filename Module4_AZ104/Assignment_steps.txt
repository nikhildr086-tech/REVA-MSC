### Task 4 – Configure VNet Peering

Configure **bidirectional peering** between:

* **Nikhil-VNET01**
* **Nikhil-DevVNET**

---

### Steps in the Azure Portal

#### Step 1: Create Peering from `Nikhil-VNET01` to `Nikhil-DevVNET`

1. Open **Virtual networks**.
2. Select **Nikhil-VNET01**.
3. In the left menu, click **Peerings**.
4. Click **+ Add**.
5. Configure:

   * **Peering link name (this VNet):** `VNET01-to-DevVNET`
   * **Remote virtual network:** `Nikhil-DevVNET`
   * **Peering link name (remote VNet):** `DevVNET-to-VNET01`
6. Leave the default options enabled (such as **Allow virtual network access**).
7. Click **Add**.

> Azure creates the peering in both directions when you configure both local and remote peering names in the same wizard.

---

### Step 2: Verify the Peering

1. Open **Nikhil-VNET01** → **Peerings**.
2. Confirm the peering status is **Connected**.
3. Open **Nikhil-DevVNET** → **Peerings**.
4. Confirm its peering status is also **Connected**.

---

### Verify Communication

To verify the VNets can communicate:

1. Deploy one virtual machine in **Nikhil-WebSubnet** (`Nikhil-VNET01`).
2. Deploy another virtual machine in **Nikhil-DevSubnet** (`Nikhil-DevVNET`).
3. Ensure the Network Security Groups (NSGs) allow ICMP or use Azure's **Connection troubleshoot** feature.
4. From one VM, ping the private IP address of the other VM, or test connectivity using:

   * `Test-NetConnection <Private-IP>` (Windows PowerShell)
   * `ping <Private-IP>` (if ICMP is allowed)
   * Azure **Network Watcher → Connection troubleshoot**

---

### Expected Result

| VNet             | Peered With      | Status        |
| ---------------- | ---------------- | ------------- |
| `Nikhil-VNET01`  | `Nikhil-DevVNET` | **Connected** |
| `Nikhil-DevVNET` | `Nikhil-VNET01`  | **Connected** |

Once both peerings show **Connected** and connectivity tests succeed, the task is complete.

### Finding your public IP

To restrict SSH or RDP to your own machine, first find your public IP address by searching **"what is my IP"** in a browser or by running:

* **PowerShell:**

  ```powershell
  (Invoke-RestMethod ifconfig.me/ip)
  ```

* **Ubuntu/Linux:**

  ```bash
  curl ifconfig.me
  ```

Use the returned IP as the **Source IP** in the NSG rules.

# Policy 1: Allow resource deployment only in one or two Azure regions

### Step 1: Open Azure Policy

* Go to **Azure Portal**
* Search for **Policy**
* Select **Definitions**

### Step 2: Find the built-in policy

Search for:

```text
Allowed locations
```

Select the built-in policy **Allowed locations**.

### Step 3: Assign the policy

Click **Assign**.

Configure:

* **Scope**:

  * Select your subscription.
  * Resource Group: **NIKHIL-RG01**

* **Policy definition**:

  * Allowed locations

### Step 4: Parameters

Select one or two regions, for example:

* **Central India**
* **South India** (optional)

Click **Review + Create** → **Create**.

This policy prevents users from deploying resources outside the selected regions.

---

### Step 1: Open Policy Definitions

```text
Require a tag on resources
```

Select it.

### Step 2: Assign the policy

Click **Assign**.

Configure:

* **Scope**

  * Subscription
  * Resource Group: **NIKHIL-RG01**

### Step 3: Parameters

Set:

* **Tag Name**

  ```
  Environment
  ```

### Method 1: Using the Azure Portal (Recommended)

| Tag Name    | Value                                         |

| Department  | IT                                            |

5. Click **Apply** or **Save**.

Repeat for every resource in **NIKHIL-RG01**.

5. If prompted with an option such as **Apply tags to resources** or **Apply to existing resources**, select it. This propagates the tags to the resources in the group.
